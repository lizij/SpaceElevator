# AGENTS.md

## Project scope

This directory contains **PROJECT ASCENT Revision 04**, an interactive Three.js space-elevator exhibit inspired by publicly available concept art for *The Wandering Earth 2*. The geometry and presentation are an original, approximate reconstruction for web display. They are not original film assets, and proportions and hidden details are intentionally adapted for the viewing experience.

This project is a member of the "same prompt × different Agent+Model" experiment collection. Experiment environment: **Trae + GPT 6 Astra**. It was migrated into the collection on 2026-10-22; the earlier standalone local-only deployment restriction recorded below is superseded by the collection's unified local + GitHub Pages deployment.

## Repository map

- `index.html`: exhibit UI and accessible controls.
- `src/main.ts`: renderer, camera, OrbitControls, animation, quality settings, screenshots, and recovery behavior.
- `src/model.ts`: procedural elevator, base, climber, orbital station, Earth, clouds, and star field.
- `src/detail.ts`: batched launch towers, mechanical fittings, and orbital service equipment.
- `src/cabin.ts`: instanced passenger seats, pressure shell, control bay, local lights, and four interior viewpoints.
- `src/rendering.ts`: solid-geometry ambient occlusion, restrained bloom, SMAA, and procedural harbor sky.
- `src/style.css`: desktop and mobile layouts.
- `public/`: files copied unchanged into the production build, including the favicon and project-generated Earth/cloud textures.
- `scripts/`: deterministic texture generation, local static server, and Playwright verification helpers.
- `SECURITY.md`: private-reporting guidance for any future distribution.
- `dist/`: generated build output; never commit it.

## Toolchain and commands

Use Node.js **22.12 or newer in the Node 22 line**. CI runs Node 22.

```bash
npm ci
npm run dev
npm run build
npm run serve
```

`npm run dev` starts Vite on `127.0.0.1`. `npm run serve` serves an existing `dist/` on `127.0.0.1:4177` and provides `/healthz`; set `PORT` to use another port.

## Interaction acceptance criteria

After changes that affect rendering, layout, input, animation, or assets, verify all relevant paths:

- Desktop: left-drag rotates, wheel zooms, right-drag pans, focus controls change targets, and the journey slider/animation/follow modes continue to work.
- Touch/mobile: one-finger rotation, two-finger pinch zoom and pan, and the 393×852 responsive control layout remain usable without clipped primary controls.
- Rendering: overview, base, climber, and orbital-station views load; Earth and cloud textures resolve; quality switching, auto-orbit, fullscreen/help, and screenshot handling do not regress.
- Cabin: aisle, seat, control, and cutaway views load; look gestures stay inside; cutaway zoom works; slider and playback preserve the camera's local position; return/reset restore exterior layers and controls. Cabin geometry/lights use layer 1; exterior uses layer 0.
- Stability: preserve separated panel surfaces and object-relative shadow placement; exclude transparent/shader geometry from the SSAO normal pass. Capture consecutive follow frames when changing depth, shadows, or postprocessing.
- Postprocessing targets must remain single-sampled: SSAOPass blends in place, and MSAA color invalidation can discard its input on tile GPUs. Its normal/depth target uses `DepthFormat`/`UnsignedIntType`, not a multisampled depth-stencil texture. Keep final SMAA for edge antialiasing.
- Accessibility/fallbacks: keyboard shortcuts and reduced-motion behavior remain intact, and WebGL failure/context-loss handling stays visible and recoverable.

At minimum, run `npm run build` after every code or asset change. For interaction-sensitive work, also install Playwright Chromium if needed and run `node scripts/run-verification.mjs`. Inspect the generated report instead of treating a successful TypeScript build as interaction coverage.

For rendering changes, also run `node scripts/run-verification.mjs verify-rendering.mjs`: high-DPI follow frames at 71%, pixel brightness/black-region assertions, quality/interior/resize switching, and WebGL error checks. `GL_INVALID_*` messages can be console **warnings**; never filter exclusively for `console.error`. The software backend alone does not establish Metal/Safari compatibility.

## Assets, references, and licensing

Procedural model geometry, panel details, labels, presentation code, and the Earth/cloud textures are maintained in this repository. The textures are deterministically generated by `npm run generate:textures`; regenerate both together after changing the algorithm. Three.js is MIT-licensed and documented in `THIRD_PARTY_NOTICES.md`. Publicly posted art-book plates collected from public web pages are kept under `references/` (including `references/private/`) for non-commercial fan research and visual comparison. They are part of this public experiment archive but are never bundled into the web application (`public/` / `dist/`). Source URLs and checksums accompany them in `references/README.md`. Before adding any new image, model, font, audio, or third-party code to the published application, confirm its license permits public GitHub and web distribution and document the source.

## Repository hygiene

Never commit secrets, credentials, tokens, `.env` files, local machine paths, `node_modules/`, `dist/`, `.runtime/`, test caches, browser profiles, or platform-specific application credentials. Keep the two generated Earth/cloud textures and the procedural model source under version control because they are part of the public deliverable.

## Deployment (collection unified pipeline)

This project no longer deploys standalone. From the collection root: `npm run install:all` installs every subproject, `npm run build` builds all subprojects and aggregates them into the root `dist/`, and `npm run serve` previews the whole collection locally. The root GitHub Actions workflow builds and publishes the hub together with every subproject in one run. Historical per-project helper scripts under `scripts/` (e.g. `service.mjs`) remain only as development utilities; the old "local-only, no remote repository" restriction from the standalone experiment is explicitly lifted by the project owner for the collection.
